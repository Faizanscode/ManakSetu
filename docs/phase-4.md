# Phase 4 - Recommendation Engine

## Architecture

The ManakSetu Recommendation Engine takes the structured output (products, applications, keywords) generated by the Phase 3 AI Requirement Analysis Engine and identifies the most relevant Indian Standards from the existing Standards Knowledge Base.

### Hybrid Matching Approach
It employs a hybrid approach, combining:
1. **Semantic Search**: Uses pgvector to compute cosine similarity between the embedded requirement string (using `gemini-embedding-2`) and the embedded text representation of each Indian Standard.
2. **Structured Metadata Matching**: Performs targeted text overlaps for extracted products, applications, and keywords against the title, description, and scope of each standard.
3. **Scope and Category Matching**: Uses specific weights when the standard specifically maps to the intent scope, category, or sector.

### Retrieval and Scoring Strategy
- **Candidate Retrieval**: Fetches standard candidates using vector search, limited to a `similarity_threshold=0.2`.
- **Scoring Formulas**: The weights applied are as follows:
  - Semantic Matching: 40% (0.40)
  - Product Metadata Matching: 20% (0.20)
  - Application Matching: 15% (0.15)
  - Keyword Matching: 10% (0.10)
  - Scope Matching: 10% (0.10)
  - Category/Sector Matching: 5% (0.05)

### API Contract

**Endpoint:** `POST /api/recommendations/`

**Request Body:**
```json
{
  "query": "Procurement requirement string (e.g., We need reinforcement steel bars...)"
}
```

**Response Body:**
```json
{
  "query": "string",
  "recommendations": [
    {
      "standard_id": "string",
      "standard_number": "string",
      "title": "string",
      "relevance_category": "string (HIGH/MEDIUM/LOW RELEVANCE)",
      "relevance_score": 0.0,
      "status": "string",
      "version": {
        "edition": "string",
        "status": "string"
      },
      "why_recommended": ["string"],

        "matched_applications": ["string"],
        "matched_keywords": ["string"],
        "scope_match": boolean,
```

## Additional Features
- **No Hallucination**: The recommendation engine strictly queries existing standard records in the PostgreSQL database. It does not generate or invent IS numbers using LLM prompting.
- **Explainability (Phase 5 Prep)**: Although Phase 5 will deepen explainability, the engine already supplies an evidence payload and deterministic score breakdown outlining precisely how a standard was retrieved.
